# M002/S03 — Cloud proof artifacts

Generated by [`tests/integration/cloud-proofs/capture-cloud-proofs.mjs`](./capture-cloud-proofs.mjs) when `MERMAID_OSS_ENDPOINT` points at a reachable S3-compatible endpoint (MinIO is the canonical dev-time target).

## What this directory proves

The v0.3.0 cloud storage path is reachable end-to-end through the **HTTP browser** path, not just the stdio MCP path proven by the S01 T04 `tests/integration/oss-proofs/` artifacts. The 4 artifacts in this directory document that the v0.3.0 `/health` JSON surface (with S03's R009 counters + last_render_ms + last_errors extension) is reachable over `MERMAID_RENDERER_BACKEND=oss`, that a curl-style request to `/health` returns HTTP/1.1 200 + `content-type: application/json` + a body that byte-matches the `/health` JSON, and that the self-contained R003 HTML viewer renders correctly for a cloud-stored entry.

## Artifacts

| File | Source | Purpose |
| --- | --- | --- |
| `browser-evidence.md` | this capture script | Markdown index of the other 3 artifacts with field-by-field assertions + reproduction steps |
| `curl.txt` | raw `http.request` GET `/health` | curl-style verbose transcript (request line + headers + response line + response headers + body) |
| `health.json` | literal `fetch('http://127.0.0.1:<port>/health').json()` body | The v0.3.0 `/health` surface over the cloud backend (status, version, data=bucket, counters, last_render_ms, last_errors) |
| `view-body.html` | literal `fetch('http://127.0.0.1:<port>/view?id=<id>').text()` body | The cloud-rendered R003 self-contained HTML viewer; deterministic text-version fallback for `view-screenshot.png` |
| `view-screenshot.png` | (not committed by this script) | The agent uses MCP `browser_navigate` + `browser_screenshot` to capture this from `view-body.html` |

## Regenerate the artifacts

```bash
# 1. Start MinIO (any S3-compatible endpoint works)
docker run -d -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=test -e MINIO_ROOT_PASSWORD=testtest \
  minio/minio server /data --console-address :9001

# 2. Create the bucket
mc alias set local http://127.0.0.1:9000 test testtest
mc mb local/mermaid

# 3. Export the 5 MERMAID_OSS_* env vars
export MERMAID_OSS_ENDPOINT=http://127.0.0.1:9000
export MERMAID_OSS_REGION=us-east-1
export MERMAID_OSS_ACCESS_KEY_ID=test
export MERMAID_OSS_SECRET_ACCESS_KEY=testtest
export MERMAID_OSS_BUCKET=mermaid

# 4. Run the capture script
node tests/integration/cloud-proofs/capture-cloud-proofs.mjs
```

The script is **MinIO-gated**: when `MERMAID_OSS_ENDPOINT` is unset or the endpoint is unreachable, the script writes a `SKIPPED` marker to `browser-evidence.md` and exits 0. This mirrors the S01 T04 + S03 T02 `describe.skipIf` semantics and keeps the script green on hosts without Docker/MinIO.

## Why a 2-entry fixture (not the S02 5-entry demo)

S02's purpose is the 4-of-5 post-sweep invariant (3 fresh+pinned, 1 expired-but-pinned, 1 expired-and-unpinned). S03's purpose is the HTTP browser path. The 2-entry fixture (1 fresh-pinned + 1 fresh-unpinned) is the minimum that exercises the bucket write path with non-trivial state and gives the migration CLI something to verify via `ListObjectsV2` after the run.

## Why a deterministic text-version fallback for the screenshot

The MCP `browser_navigate` + `browser_screenshot` tools require macOS Screen Recording permission and are host-level — they are not Node.js imports. The capture script commits `view-body.html` (the literal HTML the server returned from `/view?id=<id>`) as a deterministic text-version of the file:// view. An agent with browser MCP tools can navigate to `view-body.html` and capture `view-screenshot.png` to round out the 4-artifact set; the operator without those tools still has a complete proof via the 3 deterministic artifacts + the field-by-field assertions in `browser-evidence.md`.
